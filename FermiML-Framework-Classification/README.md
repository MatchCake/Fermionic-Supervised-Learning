## Description

Reproduction of
[Better than classical? The subtle art of benchmarking quantum machine learning models](https://arxiv.org/abs/2403.07059)
with free-fermionic models.

## Installation

### Development Dependencies

With `uv` installed, run the following commands to install the dependencies:

```bash
uv venv .venv
uv sync --dev
```

With `python` and `pip` installed, run the following commands to install the dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install uv
python -m uv sync --dev
```

With `poetry` installed, run the following commands to install the dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
poetry install
```

## Deployment

You will need to install Docker to run the trainings in a container.
You can install Docker by following the instructions [here](https://docs.docker.com/get-docker/).

To build the docker image of the project you can run the following command:

```bash
docker build -t <package_name>:latest .
```

The container can be run in two different modes:

- **release**: This mode is responsible for running the __main__.py of the current package.
- **it**: This is a development mode that is responsible for running the container in the interactive mode.

To run a mode `<mode>` you can run the following command:

```bash
docker run --name <package_name>-<phase> --detach --rm --volume=<data_path>:/<ROOT_DIR>/data -e "MODE=<mode>" <package_name>:latest <your_arguments>
```

where `<data_path>` is the absolute path in your local machine where you want to store the data generated by the phase.
The `<ROOT_DIR>` is the root directory of the project.

There is another way you can do all of this. You can use the `docker_files/build_image_and_run.py` script. This script
will build the image and run the mode you want. You can run the script with the following command:

```bash
python docker_files/build_image_and_run.py --mode=<mode>
```

## Running on the Cluster

This project uses [Snakemake](https://snakemake.readthedocs.io) with the
[SLURM executor plugin](https://snakemake.github.io/snakemake-plugin-catalog/plugins/executor/slurm.html)
to manage job submission on HPC clusters (Alliance Canada / Compute Canada).

### Prerequisites

- Apptainer (Singularity) module available on the cluster (`module load apptainer/1.4.5`)
- Project `.sif` image placed under `data/dockerfiles/` (see the Deployment section)
- Snakemake ≥ 8 and the SLURM executor plugin:

```bash
uv add --dev snakemake snakemake-executor-plugin-slurm
```

### 1. Get the experiment config

The experiment configuration is at `data/configs/config_20splits.yaml`.
Make sure this file is present on the cluster (it is tracked in the repository,
so a `git pull` is sufficient).

### 2. Dry-run

Preview all jobs that Snakemake would submit without running anything:

```bash
uv run python -m snakemake --snakefile workflow/Snakefile --cores 1 -n
```

### 3. Submit to the cluster

From the login node, launch the full experiment using the bundled SLURM profile:

```bash
uv run python -m snakemake --snakefile workflow/Snakefile \
    --profile workflow/profiles/slurm
```

Snakemake submits one independent SLURM job per unfinished experiment config.
Jobs whose `state.finished` file already exists are automatically skipped —
re-running the command safely resumes where it left off.

**Common flags:**

| Flag                 | Effect                                           |
|----------------------|--------------------------------------------------|
| `-n`                 | Dry-run: print the job DAG without submitting    |
| `--forceall`         | Re-run all jobs, even finished ones              |
| `--rerun-incomplete` | Retry jobs that started but did not finish       |
| `--jobs N`           | Override the cap on concurrent SLURM submissions |

### 4. Monitor progress

```bash
squeue -u $USER
squeue -u $USER -h -r -O state | uniq -c   # counts by state
```

Per-job logs are written to `data/{experiment_name}/logs/snakemake/{hash}.log`.

### Customising resources or the experiment

| File                                  | Purpose                                                                 |
|---------------------------------------|-------------------------------------------------------------------------|
| `workflow/config.yaml`                | Active experiment name, config path, SIF version                        |
| `workflow/profiles/slurm/config.yaml` | Default SLURM account, memory, time limit                               |
| `workflow/Snakefile`                  | Rule definitions; add per-rule `resources:` blocks to override defaults |

To switch to a different experiment, update `config_file` in `workflow/config.yaml`
to point to the new config.
